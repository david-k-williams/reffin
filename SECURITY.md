# Security Policy

## Supported versions

Until Reffin publishes versioned releases, security fixes are made on the
`main` branch. After releases begin, only the latest released version and
`main` will receive security fixes.

## Reporting a vulnerability

Please report vulnerabilities privately through
[GitHub Security Advisories](https://github.com/david-k-williams/reffin/security/advisories/new).
Do not open a public issue for an unpatched vulnerability.

Include, when possible:

- the affected package, language, version, or commit;
- a minimal reproduction or proof of concept;
- the expected security impact;
- any known mitigations; and
- whether the report contains information that should remain private.

You should receive an acknowledgement within five business days. Investigation
and remediation timelines depend on severity and complexity. We will coordinate
disclosure with the reporter and credit the report unless anonymity is
requested.

If private vulnerability reporting is unavailable, open a public issue asking
for a private contact method without including vulnerability details.

Reference-data corrections that do not create a security risk should use the
[data correction issue form](https://github.com/david-k-williams/reffin/issues/new?template=data_correction.yml).
